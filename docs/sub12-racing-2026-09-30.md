## Selected classical driver

`race_ws/src/team_driver/config/fast_corner_24_map72_safety28_params.yaml`
is the fastest repeatably clean scored setup on the connected AutoDRIVE
compete build and `icra26_compete` track. It keeps the original packaged

The selected config requests 7.2 m/s on map-certified straights and a
24 m/s^2 cornering allowance. Its LiDAR speed cap uses 2.8 m/s^2 braking,
matching the 2.798 m/s^2 estimate in `vehicle_limits.yaml`; it does not
change the simulator's physical acceleration. The short lookahead setting
uses a 1.5 m maximum and 0.25 speed gain. These are planning settings, not

## What was tried

- The prior map-certified 7.2 m/s, 16 m/s^2 setup ran two clean ten-lap
  sessions, with 12.492 and 12.489 s best laps. It remains a separate
  rollback config, `fast_corner_16_map72_short_params.yaml`.
- Increasing the straight request to 8.5 m/s scored 12.668 s best over three
  clean laps. A telemetry trace on a comparable candidate peaked at 6.52
  m/s; the tight hairpins, rather than the requested speed ceiling, dominated
  lap time. A 9.5 m/s candidate was not scored after that finding.
- Increasing requested planner acceleration to 5.0 m/s^2 scored 12.664 s
  best over three clean laps. The experimental override was removed from
  runtime code after it failed to improve the score. The measured limits file
  was never changed.
- Corner allowances of 20, 24, and 32 m/s^2 were clean in three-lap pilots,
  with best laps of 12.601, 12.506, and 12.588 s respectively while the
  LiDAR braking cap remained at 2.0 m/s^2. The 24 m/s^2 setting was retained
  for the braking-cap trial.
- A broad lane offset collided in all three timed laps. A separate local
  hairpin line change passed map clearance and completed three clean laps,
  but its 12.591 s best was slower than the unchanged line's 12.506 s pilot.
  Neither line change was adopted.
- Fixed 25 ms controller timing scored 12.713 s best in a three-lap pilot
  and was rejected.

The real-time factor was about 0.72 in both selected full runs. The referee
reports simulator lap times, but simulator pacing may still affect controller
behavior, so the proof here is the completed scored sessions under the
connected setup, not a guarantee on another machine or build.

## V2 residual actor

The continued SAC v2 actor at
`race_ws/src/team_driver/weights/residual_policy_v2_map72_safe_candidate.npz`
finished ten scored laps with zero collisions or penalties: best 12.726 s,

collision and action penalties. The clean scored output is
`results/submitted/rl_v2_map72_step2000_full__20260930T033229Z.json`.
This actor is preserved as a clean v2 candidate, but the selected sub-12
driver is classical; the actor has not been shown to beat it and was trained
against the earlier 16 m/s^2, 7.2 m/s baseline.

## Connect and drive

Use the Windows AutoDRIVE compete application with its existing track and
settings. Inside the running Docker container, build the team package and
source the ROS overlays. In one container shell start the bridge:

```bash
ros2 launch roboracer_referee simulator.launch.py simulator:=false rviz:=false
```

In AutoDRIVE's Menu Panel, connect to `127.0.0.1:4567` and set the vehicle
to Autonomous. In a second container shell, with the same overlays sourced,
run from `race_ws/src/team_driver`:

```bash
ros2 run team_driver driver --ros-args \
  --params-file "$(pwd)/config/fast_corner_24_map72_safety28_params.yaml"
```

Stop any other driver process before launching this one. To reproduce a
scored run, start `evaluate.launch.py` with `simulator:=false`, the selected
`driver_params` path, `warmup_laps:=2`, and `timed_laps:=10`; that launch
starts its own driver, so stop the manual driver first.
